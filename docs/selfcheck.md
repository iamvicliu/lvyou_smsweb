# 绿邮面板全套自检

这是一次性、只读的全链路自检，用来回答“面板、五块板、信号和记录入库现在到底有没有问题”。它不是定时任务，也不会重启卡槽、发短信或拨号。

## 运行

在仓库根目录执行：

```bash
cd /Users/vicliu/Github/lvyou_smsweb
./scripts/selfcheck.sh
```

脚本会先检查本机是否能通过局域网直连 `n1`；能直连就不使用 frp。只有在不在家、局域网连不上时才回退到 `n1-frp`。运行时把 `selfcheck.py` 临时复制到容器，执行完立即删除。

不要为了自检主动启停 frpc。

## 检查顺序

1. **面板本身**
   - `/api/health`：确认服务返回 200。
   - 容器时区：确认使用北京时间。
   - Bark：检查保存的推送域名能否解析、能否建立 HTTPS。面板断外网时这里只报 WARN，因为短信入库仍可正常。
2. **每块板逐台检查**，顺序与首页卡片一致：
   - 998 心跳：是否仍在厂商建议的时间窗口内。
   - `askinf`：板子能否正常响应、响应耗时。
   - 板子时钟：与面板时间的偏差；超过 3 分钟报 WARN，超过 10 分钟报 FAIL。
   - `storesmstelen`：两个卡槽的短信、通话存储是否都开启。
   - `askallmsgcode`：998、501、502、601、602、603 推送消息号是否开启。
   - `askinf` 推送地址：是否指向当前面板的 `:34567`。
   - `askcustmsg`：检查是否存在 501、502、603 的自定义 Bark 文本模板；存在时显示 INFO，面板应能解析。
3. **板端与面板对账**
   - 每个卡槽执行 `querysms`，把板端最近短信与面板数据库按时间、号码后四位逐条比对。
   - 执行 `querytel`，把板端最近通话与面板数据库按通话开始时间比对。
   - 缺少任何一条都报 FAIL；这比只看心跳更能发现“板子在线但短信没进面板”。
4. **卡状态**
   - 输出两个卡槽当前的运营商、信号或异常状态，方便判断“板子链路正常，但卡本身不可用”。

## 结果怎么读

- `PASS`：这一项通过。
- `WARN`：核心链路仍可用，但存在外部条件或建议处理项。例如路由器没有外网导致 Bark 域名解析失败。
- `FAIL`：必须处理，通常是服务异常、板子不可达、存储/推送开关缺失、时钟偏差过大，或板端记录没有进入面板。
- `INFO`：配置或卡状态说明，不是错误。

最后一行：

```text
结论：PASS  失败 0 项 / 警告 1 项
```

退出码 `0` 表示没有 FAIL（可以有 WARN）；退出码 `1` 表示存在 FAIL。

## 常见判断

| 现象 | 优先判断 |
|---|---|
| 面板健康失败 | 先查 `lvyou-smsweb` 容器和 `:34567` |
| 心跳失败、`askinf` 也失败 | 板子掉线或局域网地址变化 |
| 心跳正常、`askinf` 失败 | 板子 Web 接口异常或凭据失效 |
| 时钟偏差大 | 会影响记录排序，应重新校准板子 |
| 存储未全开 | 板子重启后才会生效 |
| 推送开关缺失 | 板子不会主动上报该类消息 |
| 推送地址不是本面板 | 板子可能仍在向旧地址推送 |
| 短信/通话对账缺记录 | 推送漏了，或面板没有成功入库 |
| 仅 Bark WARN | 通常是路由器断网，不影响短信入库 |

## 安全边界

- 全程只读，不对板子做写操作。
- 不主动发送短信、不拨号，避免产生费用。
- 不重启卡槽，不修改存储、推送和自动接听配置。
- 不打印密码、上传令牌、完整手机号或短信正文。
